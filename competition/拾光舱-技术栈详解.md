# 拾光舱 · 技术栈详解

> 版本：v1.0.2 · 最后更新：2026-07-27
> 跨平台桌面应用 · 摄影师可信影像仓库 + 追光百宝箱

---

## 一、项目概述

拾光舱是一款基于 **Electron** 的跨平台桌面应用（macOS + Windows），由三层架构组成：

```
┌─────────────────────────────────────────────────┐
│   Electron 主进程（系统托盘 + 后端生命周期）        │
│                  ↕ IPC / fork                    │
├─────────────────────────────────────────────────┤
│   Node.js + Express 后端（端口 9901）             │
│   ┌──────────────┐  ┌──────────────────────┐    │
│   │  真实归档     │  │  追光百宝箱           │    │
│   │  文件/EXIF   │  │  Open-Meteo API     │    │
│   └──────────────┘  └──────────────────────┘    │
├─────────────────────────────────────────────────┤
│   React 19 + Vite 前端（端口 9900）              │
│   Dashboard / Gallery / Import / LightHunt      │
└─────────────────────────────────────────────────┘
```

| 端口 | 用途 |
|---|---|
| 9900 | 前端开发服务器（Vite） |
| 9901 | 后端 API 服务（Express） |

  - Windows：NSIS 安装包，x64，可自定义安装目录

## 四、关键技术亮点

### 1. 清单基础设施（ManifestService）

- 每仓库维护 `repo/.shiguang/manifest.json`，结构 `{ version, lastUpdated, files: { relPath: { hash, size, mtime, exif } } }`
- **30 秒内存缓存**减少磁盘 IO
- **hash 反向索引 Map**（`hash → relPath`）实现 O(1) 去重查找
- 首次访问扁平结构仓库自动初始化清单
- 支持 `deleteManifest` + `initFromScan` 重建

### 2. 流式哈希 + 兜底去重

- `crypto.createHash('sha256')` + `fs.createReadStream` 流式计算，适合大文件
- 双层去重：① 清单 hash 反查 ② 目标路径已存在时再算哈希比对
- 哈希前缀 `sha256:` 便于未来扩展其他算法

### 3. 并发控制（runWithConcurrency）

```javascript
async function runWithConcurrency(items, concurrency, asyncFn) {
  let index = 0;
  async function worker() {
    while (index < items.length) {
      const i = index++;
      await asyncFn(items[i], i);
    }
  }
  const workers = Array(Math.min(concurrency, items.length)).fill(0).map(worker);
  await Promise.all(workers);
}
```

- IO 密集型（文件复制）：并发度 8
- EXIF 读取：并发度 6（exiftool 单实例约 100ms/文件）

### 4. EXIF 数值解析容错

exiftool-vendored 返回的数值字段可能带单位（`"70 mm"`、`"f/4"`），直接 `Number()` 得 NaN。`parseExifNumber` 用正则提取首个合法数字，兼容所有带单位字符串。

### 5. RAW 缩略图三级降级

1. exiftool 提取嵌入预览（`JpgFromRaw` / `PreviewImage` / `ThumbnailImage` 三个标签依次尝试）
2. sharp 直接解码 RAW
3. 返回 null，前端用占位 SVG

### 6. 跨平台文件夹选择对话框

四级降级策略：
- Electron IPC（主进程 `dialog.showOpenDialog`，推荐）
- PowerShell `FolderBrowserDialog`（Windows 回退）
- VBScript `Shell.Application`（Windows 终极回退）
- osascript（macOS）/ zenity（Linux）

### 7. Open-Meteo 双 endpoint 容错

- `Promise.allSettled` 并发 forecast + air-quality
- forecast 是核心数据，失败整体抛错
- air-quality 失败时返回 null，评分模块走 AOD fallback（0.3 保守降权）
- 第 5-7 天 AOD 缺失（air-quality 仅 4.5 天预报），UI 灰底标记不确定性

### 8. 星轨评分零网络成本

月相算法完全在前端用 `suncalc` 纯 JS 库计算，不增加 Open-Meteo 配额；夜间云量复用后端同一次 forecast 请求，零增量网络成本——这是星轨基础版能低成本并入 v1.0.2 的关键。

### 9. macOS DMG 构建容错

构建脚本（[build-mac.js](file:///Users/colorh/Project/AICODING/photo_manager/scripts/build-mac.js)）三级降级：
1. electron-builder 内置 dmgbuild
2. 自定义 dmg-builder bundle（离线 tar.gz，内置 Python）
3. `hdiutil` 命令行直接生成 + `codesign --force --deep --sign -` ad-hoc 签名

并清除 `PYTHONHOME` 环境变量，避免破坏 dmgbuild 内嵌 Python 的标准库查找。

## 六、技术选型决策摘要

| 决策点 | 选型 | 理由 |
|---|---|---|
| 桌面框架 | Electron | 跨平台 + 复用 Web 技术栈 + 系统托盘/通知原生能力 |
| 后端 | Node.js + Express | 与前端同语言，IO 密集型场景性能足够 |
| UI 库 | Ant Design 6 | 企业级组件齐全，中文生态好，主题定制能力强 |
| 构建 | Vite 8 | 开发期 HMR 极快，配置简单 |
| EXIF | exiftool-vendored | 行业标准，精度高，支持所有相机 RAW 格式 |
| 图像处理 | sharp | 性能最佳（libvips），RAW 解码 + 缩略图 + 旋转一站搞定 |
| 天文计算 | suncalc | 纯 JS 算法，零网络成本，月相不占 API 配额 |
| 气象数据 | Open-Meteo | 免费层 10k/天，覆盖全球，无需 API Key |
| 数据存储 | JSON 文件 | 无数据库依赖，本地工具天然适合，便于备份迁移 |
| 进度推送 | SSE | 单向推送，比 WebSocket 简单，浏览器原生支持 |
| 哈希 | SHA-256 | 抗碰撞性强，行业通用，流式计算适合大文件 |
